# Scaffolding up to secrets — Google Calendar + Health OAuth

**Branch:** `cursor/scaffolding-up-to-secrets-3696`  
**Date:** 2026-09-08  

## What this ships (no secrets required)

Honest Google OAuth scaffolding that stops at the credentials/token boundary:

| Surface | Without secrets | With `GOOGLE_CLIENT_*` | With live token |
|---|---|---|---|
| Calendar | `needs_credentials` | `configured` + `auth_url` | `connected`; `/events` live pull |
| Health API | `needs_credentials` | `configured` + `auth_url` | `token_ready` (dataset sync next) |
| Takeout ZIP | unchanged primary offline path | — | — |
| Fitbit | legacy fixture only | — | not primary |

## APIs

- `GET /api/google/calendar/{status,auth,callback}` · `GET .../events` · `POST .../revoke`
- `GET /api/google/health/{status,auth,callback}` · `POST .../pull` · `POST .../revoke`
- Encrypted token store: `backend/connectors/token_store.py` → `data/aegis_oauth.sqlite3`

## Env

See `.env.example`: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, redirect URIs, optional `AEGIS_TOKEN_KEY`.
